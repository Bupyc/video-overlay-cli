# video-overlay-cli

[English](README.md) | Русский

Go-программа командной строки для создания телеметрических оверлеев из FIT- и GPX-файлов активности с помощью XML-шаблонов. Экспортируйте прозрачный оверлей, оверлей на чёрном фоне или наложите его на готовое видео.

Рендерер написан на Go; замеры производительности проводились на macOS с Apple Silicon. FFmpeg отвечает за кодирование и, при необходимости, композитинг с исходным видео. Телеметрия читается из FIT/GPX, а не извлекается из видео.

## Отличия от оригинального Python-проекта

Сравнение ведётся с неизменённым upstream [`gopro-dashboard-overlay` на коммите `8e26ee5`](https://github.com/time4tea/gopro-dashboard-overlay/tree/8e26ee5b452c6aefa38aa6d08557f15139b61e6c) от 16 мая 2026 года. Замеры производительности используют изменённую локальную Python-копию только как тестовый ориентир.

- **Ctrl+C:** FFmpeg корректно закрывает частичный экспорт, поэтому файл остаётся читаемым.
- **Источники данных:** Go читает FIT и GPX. Извлечения GPMF из видео GoPro нет; `--video` используется только для композитинга.
- **Метрики трейлов:** добавлены адаптивные окна для темпа, временного уклона и вертикальной скорости, расчёт уклона по дистанции FIT и беговой каденс в шагах в минуту. В исходном проекте этих трейловых улучшений и вертикальной скорости нет. См. [справку по метрикам](docs/metrics.ru.md).
- **Параллельная обработка:** кадры рендерятся параллельно; подготовленный рендерер и кэши общие. В прозрачном режиме число активных воркеров подстраивается под давление со стороны FFmpeg в пределах `--workers`. Подготовка метрик остаётся последовательной, как в upstream.
- **Шаблоны:** сохранён XML-формат. Список компонентов и ограничений — в [таблице виджетов](docs/widget-matrix.ru.md); рендер не полностью совпадает с Python, особенно текст и растеризация.
- **Редактор:** у CLI нет визуального редактора шаблонов. UI ведётся как отдельный проект и пока не реализован.
- **Производительность:** [замеры](docs/performance.ru.md) сделаны на изменённой Python-копии и синтетическом GPX; это не сравнение с неизменённым upstream.

## Требования и сборка

- Go 1.27.3 или новее.
- FFmpeg 8 или совместимая сборка: `prores_ks` для `alpha-prores`, `hevc_videotoolbox` на macOS для `alpha-hevc`, `libvpx-vp9` для `alpha-vp9` и `libx264` для `black-h264`.
- Установленный шрифт. По умолчанию рендерер ищет Roboto Medium, затем системные шрифты Arial в macOS. Другой файл укажите через `--font`.

```sh
go build -o video-overlay-cli ./cmd/video-overlay-cli
./video-overlay-cli --help
./video-overlay-cli render --help
```

## Быстрый запуск

Экспортировать отдельный прозрачный оверлей:

```sh
./video-overlay-cli render \
  --activity activity.fit \
  --layout layouts/virb-run.xml \
  --output run-overlay.mov \
  --size 1920x1080 --fps 10 \
  --background transparent --profile alpha-prores
```

Экспортировать оверлей на чёрном фоне:

```sh
./video-overlay-cli render \
  --activity ride.gpx \
  --layout layouts/virb-bike.xml \
  --output bike-overlay.mp4 \
  --size 1920x1080 --fps 10 \
  --background black --profile black-h264
```

Встроенный профиль `black-h264` использует `yuv420p`, поэтому ширина и высота кадра должны быть чётными, если формат пикселей FFmpeg не задан явно.

Для прозрачного MOV с меньшим размером выберите `--profile alpha-hevc` (macOS). Для прозрачного WebM используйте `--profile alpha-vp9`; путь результата должен заканчиваться на `.webm`.

```sh
./video-overlay-cli render --activity activity.fit --layout layouts/virb-run.xml \
  --output run-overlay-vp9.webm --size 1920x1080 --fps 10 \
  --background transparent --profile alpha-vp9
```

VP9 по умолчанию настроен на скорость (`realtime`, `cpu-used=8`, 16 потоков, 8 столбцов тайлов). Это может увеличить размер и снизить эффективность сжатия. HEVC Alpha также использует скоростной режим VideoToolbox. Параметры кодировщика можно переопределять через `--ffmpeg-arg`.

## Скорость и размер режимов экспорта

Примерные результаты на M4 Pro для одного и того же синтетического трейлового GPX длительностью 179,9 секунды, `layouts/virb-run.xml`, 1920×1080, 10 кадров/с и 8 воркеров. FPS здесь — скорость экспорта; видео воспроизводится с частотой 10 кадров/с. Размер на час линейно оценён по тестовому файлу.

| Профиль | Результат | Скорость экспорта | Примерный размер за час | Когда выбирать |
|---|---|---:|---:|---|
| `alpha-prores` | Прозрачный ProRes 4444 MOV | 110 кадров/с | 8,0 ГБ | Качественный мастер-файл для монтажа. |
| `alpha-hevc` | Прозрачный HEVC MOV | 179 кадров/с | 265 МБ | Небольшой MOV с альфа-каналом; проверьте поддержку HEVC Alpha в приложении. |
| `alpha-vp9` | Прозрачный VP9 WebM | 283 кадра/с | 71 МБ | Быстрый компактный файл, если приложение поддерживает VP9 Alpha в WebM. |
| `black-h264` | Непрозрачный H.264 MP4 на чёрном фоне | 706 кадров/с | 20 МБ | Альфа-канал не нужен и подходит чёрный фон. |

ProRes подходит для мастер-файлов, HEVC — для MOV с альфа-каналом, VP9 — для скорости и компактности при поддержке целевым приложением. `black-h264` — самый быстрый и компактный из измеренных режимов, но прозрачность он не сохраняет. Реальные значения зависят от содержимого, шаблона, числа воркеров и версии FFmpeg. Методика подробно описана в [заметках о производительности](docs/performance.ru.md).

## Прогресс и Ctrl+C

В интерактивном терминале индикатор показывает FPS экспорта, затраченное время, текущую секунду видео из общей длительности и примерное оставшееся время. По завершении выводятся общее время и средний FPS. При Ctrl+C рендер останавливается на границе кадра, после чего FFmpeg закрывает частичный файл. Такой файл остаётся читаемым.

## Композитинг с исходным видео

Телеметрия загружается из FIT/GPX; видео используется только как фон. Звук исходника копируется, если он есть. Положительный `--video-offset` сдвигает оверлей позже начала видео, отрицательный — раньше.

```sh
./video-overlay-cli render --activity activity.fit --layout layouts/virb-run.xml \
  --output run-composite.mp4 --video camera.mov --video-offset 12.4 \
  --size 1920x1080 --fps 10 --background transparent --profile black-h264
```

## Шаблоны и метрики

Шаблоны используют XML-формат. В [`layouts/`](layouts/) есть варианты для бега и велосипеда, а в [`examples/`](examples/) — галереи и примеры из исходного проекта. Названия компонентов принимают дефисы и подчёркивания. Подробности о виджетах и известные ограничения приведены в [таблице виджетов](docs/widget-matrix.ru.md).

Доступны скорость, темп, дистанция, высота, уклон, вертикальная скорость, пульс, каденс, мощность, температура, время и GPS-данные. При медленном темпе темп рассчитывается по 30-секундному окну; временные уклон и вертикальная скорость могут использовать окна до 120 секунд. Подробности — в [справке по метрикам](docs/metrics.ru.md).

Карты с тайлами по умолчанию используют OpenStreetMap, показывают атрибуцию и кэшируют тайлы в системной папке пользователя. Для загрузки новых тайлов требуется сеть. Параметры `--tile-url`, `--tile-cache`, `--tile-attribution` настраивают источник тайлов; `--privacy LAT,LON,KM` скрывает детали в заданном радиусе.

## Разработка

```sh
go build ./cmd/video-overlay-cli
go test ./...
```

CLI поддерживает команду `render`. Визуального редактора XML-шаблонов в этом проекте нет.

Чтобы опубликовать бинарники, отправьте тег версии, например `v1.0.0`. После успешных тестов и сборки GitHub Actions создаст или обновит Release с бинарниками для Linux x64, Windows x64 и macOS Apple Silicon и автоматически сформированными заметками:

git tag v1.0.0
