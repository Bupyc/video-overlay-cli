# Использование

[English](usage.md) | Русский

## Требования

- Go 1.27.3 или новее для сборки или запуска из исходников.
- FFmpeg 8 или совместимая версия: `prores_ks` для ProRes Alpha, `hevc_videotoolbox` на macOS для HEVC Alpha, `libvpx-vp9` для VP9 Alpha и `libx264` для H.264.
- Установленный шрифт. По умолчанию используется Roboto Medium, затем системный Arial в macOS. Другой файл можно указать через `--font PATH`.

```sh
go build -o video-overlay-cli ./cmd/video-overlay-cli
./video-overlay-cli --help
./video-overlay-cli render --help
```

CLI отрисовывает кадры на Go и передаёт их в FFmpeg для кодирования. С параметром `--video` FFmpeg также накладывает оверлей на исходное видео.

## Экспорт отдельного оверлея

По умолчанию создаётся отдельный оверлей на всю длительность активности без открытия исходного видео.

```sh
./video-overlay-cli render \
  --activity activity.fit \
  --layout layouts/virb-run.xml \
  --output run-overlay.mov \
  --size 1920x1080 --fps 10 --workers 4 \
  --background transparent --profile alpha-prores
```

`alpha-prores` передаёт кадры RGBA в ProRes 4444 (`prores_ks`, `yuva444p10le`) с альфа-каналом. FFmpeg может сообщить для потока `yuva444p12le`; свойства можно проверить командой `ffprobe`.

Для небольшого MOV с потерями и альфа-каналом на macOS используйте `--profile alpha-hevc`. Кодирование выполняется через VideoToolbox из BGRA с качеством альфа-канала 0.8. Перед финальным экспортом проверьте края цветного текста на нужном фоне:

```sh
./video-overlay-cli render --activity activity.fit --layout layouts/virb-run.xml \
  --output run-overlay-hevc.mov --size 1920x1080 --fps 10 \
  --background transparent --profile alpha-hevc
```

HEVC Alpha настроен на скорость. `ffprobe` может показать `pix_fmt=yuv420p`, поскольку сообщает формат базового слоя; для проверки прозрачности используйте совместимый с HEVC Alpha декодер Apple.

Для прозрачного WebM используйте профиль VP9. По умолчанию он использует CRF 32, `yuva420p` и отключает альтернативные опорные кадры, чтобы сохранить альфа-канал. Настройки для скорости: `deadline=realtime`, `cpu-used=8`, 16 потоков и 8 столбцов тайлов. Они могут увеличить размер файла и снизить эффективность сжатия относительно более медленного кодирования.

```sh
./video-overlay-cli render --activity activity.fit --layout layouts/virb-run.xml \
  --output run-overlay-vp9.webm --size 1920x1080 --fps 10 \
  --background transparent --profile alpha-vp9
```

Поддержка VP9 Alpha зависит от декодера и целевого приложения. Встроенный декодер VP9 в FFmpeg может показывать только цветовые плоскости. Проверьте прозрачность в приложении, где будете использовать оверлей.

## Профили FFmpeg и пользовательские параметры

`--profile` выбирает встроенный формат вывода: `alpha-prores`, `alpha-hevc`, `alpha-vp9` или `black-h264`. Параметр `--ffmpeg-profile NAME` загружает именованный JSON-профиль с массивами аргументов `input` и `output` и необязательным полем `filter` для композитинга с `--video`. По умолчанию профили читаются из `video-overlay-cli/ffmpeg-profiles.json` в пользовательской папке настроек ОС; другой файл задаётся через `--ffmpeg-profiles PATH`. Пользовательский фильтр должен оставлять выход без метки для автоматического сопоставления FFmpeg; если фильтр помечает выходы, добавьте соответствующий `-map` в `output`. Формат профиля совпадает с форматом исходного Python-инструмента. Пример: [`../examples/ffmpeg-profiles.example.json`](../examples/ffmpeg-profiles.example.json).

Для разовой настройки повторяйте `--ffmpeg-arg` для каждого токена аргумента. Эти параметры добавляются после настроек кодировщика и именованного профиля. Например, `--ffmpeg-arg=-crf --ffmpeg-arg=28` задаёт более высокое качество VP9. Позиция параметров FFmpeg относительно входных и выходных файлов важна; пользовательские аргументы могут нарушить настройки альфа-канала или контейнера.

Для непрозрачного оверлея на чёрном фоне используйте `--background black` вместе с `--profile black-h264`:

```sh
./video-overlay-cli render --activity ride.gpx --layout layouts/virb-bike.xml \
  --output bike-overlay.mp4 --size 1920x1080 --fps 10 \
  --background black --profile black-h264
```

Для отдельного оверлея `black-h264` требует `--background black`, а профили с альфа-каналом — `--background transparent`. Встроенный вариант `black-h264` использует `yuv420p`, поэтому ширина и высота кадра должны быть чётными, если формат пикселей FFmpeg не задан явно. H.264 не сохраняет альфа-канал. При композитинге с `--video` прозрачный оверлей можно наложить и сохранить как непрозрачное видео H.264. Свойства результата можно посмотреть через `ffprobe`:

```sh
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,pix_fmt \
  -of default=noprint_wrappers=1 run-overlay.mov
```

## Композитинг с исходным видео

Параметр `--video PATH` просит FFmpeg наложить созданный оверлей на исходное видео. Телеметрия из видео не извлекается. Оверлей должен иметь прозрачный фон. `--video-offset SEC` сдвигает его временную шкалу относительно исходного видео: положительное значение запускает оверлей позже, отрицательное — раньше. По умолчанию сдвиг равен нулю. Звук исходника копируется, если он есть; видео масштабируется до `--size`.

```sh
./video-overlay-cli render --activity activity.fit --layout layouts/virb-run.xml \
  --output run-composed.mov --video camera.mov --video-offset 12.4 \
  --size 1920x1080 --fps 10 --background transparent --profile black-h264
```

Запускается один процесс FFmpeg, кадры передаются через stdin в формате пикселей, заданном профилем. Исходное видео должно читаться, а путь результата должен отличаться от файлов активности, шаблона и исходного видео.

## Шаблоны, шрифты и иконки

Шаблоны используют XML-формат. Названия компонентов могут содержать дефисы и подчёркивания. Список XML-компонентов и внутренних виджетов, недоступных через CLI, приведён в [таблице виджетов](widget-matrix.ru.md).

Пользовательские иконки ищутся относительно XML-файла, затем по указанному пути. Встроенные иконки включены в исполняемый файл. Неподдерживаемый XML-компонент сообщает свой тип и расположение до запуска FFmpeg.

Карты с тайлами по умолчанию используют OpenStreetMap и показывают атрибуцию. Для загрузки новых тайлов требуется сеть. Параметры `--tile-url`, `--tile-cache` и `--tile-attribution` позволяют указать другой совместимый источник. `--privacy LAT,LON,KM` скрывает карту в заданном радиусе и разрывает линию маршрута в скрытых точках.

## Прогресс и завершение по Ctrl+C

В интерактивном терминале индикатор показывает FPS экспорта, прошедшее время, текущую секунду видео относительно полной длительности и ETA. По завершении рендера выводятся путь, число кадров, затраченное время и средний FPS.

При нажатии Ctrl+C CLI останавливает генерацию кадров и корректно закрывает FFmpeg, чтобы тот финализировал частичный файл. Файл остаётся читаемым. Путь к нему выводится в сообщении `Interrupted; finalized partial output`; код завершения — 130.

## Ошибки и коды завершения

Некорректные файлы активности, шаблоны, виджеты, размеры, профили, шрифты и видео проверяются до запуска FFmpeg. Ошибки FFmpeg содержат его диагностику. Ошибки команды выводятся в stderr; обычная ошибка завершается с кодом 2, прерывание через Ctrl+C — с кодом 130. Существующий выходной файл заменяется только после проверки входных данных и XML. Не указывайте один и тот же путь для результата и входного файла.
