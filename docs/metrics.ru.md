# Справочник метрик

[English](metrics.md) | Русский

Идентификаторы встроенных метрик в таблице ниже — точные имена XML-полей строчными буквами; они не переводятся. Для пользовательского поля FIT указывайте его точное имя, сохраняя регистр и пробелы.

```xml
<component type="metric" x="16" y="24" metric="Battery Level"
           custom_field="true" dp="0" size="32"/>
```

Для чтения именованного числового поля FIT укажите `custom_field="true"` у `<component type="metric">`, а в `metric` — точное имя поля из FIT. Сопоставление чувствительно к регистру и включает Developer Fields, описанные в FIT-файле. Числовые поля из сообщений `record` меняются вместе с точками активности и интерполируются между ними; поля из `session` постоянны для всей активности. Строки, массивы и значения только из других типов сообщений этим параметром не поддерживаются. Единицы FIT не добавляются и не преобразуются автоматически; `units` запускает стандартные преобразования, поэтому оставляйте его пустым, если значение пользовательского поля уже выражено в нужных единицах. Если значения нет, выводится `-`.

Для встроенных метрик атрибут `units` преобразует числовое значение для вывода, а `format` задаёт числовой формат. Для `pace` используйте `units="pace_km"` или `units="pace_mi"` (при желании вместе с `format="pace"`). Без `format` метрика `elapsed` выводится как `HH:MM:SS`; с `format` показывается её числовое значение в секундах. Если значения встроенной метрики нет, выводится `-` (для `pace` — `—`).

## Поля

| Идентификатор в XML | Что выводит |
| --- | --- |
| `hr` | Записанный пульс, уд/мин. |
| `cadence` | Записанное значение каденса. В беге оно используется для расчёта `running_cadence`. |
| `running_cadence` | Беговой каденс в шагах/мин; если не выбран профиль велосипеда, рассчитывается как `cadence × 2`. |
| `power` | Записанная мощность, Вт. |
| `temp` | Записанная температура, по умолчанию °C. |
| `respiration` | Частота дыхания из FIT, вдохов/мин. |
| `sdps` | Значение поля FIT `sdps` без преобразования. |
| `gear.front` | Номер передней передачи из событий FIT; последнее значение сохраняется до следующего события. |
| `gear.rear` | Номер задней передачи из событий FIT; последнее значение сохраняется до следующего события. |
| `speed` | Сглаженная записанная скорость, если она есть; иначе скорость GPS за короткое окно. Базовая единица — м/с. |
| `raw_speed` | Записанная скорость до сглаживания. Базовая единица — м/с. |
| `cspeed` | Сглаженная фильтром Калмана скорость GPS за короткое окно. Базовая единица — м/с. |
| `cspeed.k` | Псевдоним `cspeed`. |
| `cspeed.raw` | Скорость GPS за короткое окно до сглаживания фильтром Калмана. Базовая единица — м/с. |
| `lspeed` | Скорость за длинное окно: используется дистанция FIT, если она есть, иначе дистанция GPS. Базовая единица — м/с. |
| `pace` | Темп по выбранной скорости. Для мин/км укажите `units="pace_km"`, для мин/мили — `units="pace_mi"`. |
| `accel` | Изменение записанной скорости за короткое окно. Базовая единица — м/с²; без записанной скорости значения нет. |
| `dist` | Прирост дистанции для точки, в метрах. Если доступен, используется прирост по короткому окну GPS. |
| `odo` | Накопленная дистанция FIT, если она есть в точке; иначе накопленная дистанция GPS. Базовая единица — метры. |
| `codo` | Накопленная дистанция, рассчитанная по GPS, в метрах. |
| `alt` | Записанная высота, по умолчанию в метрах. |
| `gradient` | Выбранный уклон в процентах: по дистанции FIT, если это возможно, иначе оценка GPS по временному окну. |
| `cgrad` | Уклон по GPS за короткое временное окно, в процентах. |
| `vertical_speed` | Записанная вертикальная скорость, если она есть; иначе адаптивная оценка. Базовая единица — м/с; `units="m/h"` или `units="ft/h"` выводит скорость за час. |
| `cvspeed` | Производная вертикальная скорость за короткое окно. Базовая единица — м/с. |
| `lvspeed` | Производная вертикальная скорость за длинное окно. Базовая единица — м/с. |
| `xlvspeed` | Производная вертикальная скорость за очень длинное окно. Базовая единица — м/с. |
| `time` | Секунды между точками, используемыми для расчёта скорости GPS за короткое окно. Это интервал расчёта, а не время от начала активности. |
| `elapsed` | Секунды от начала активности. По умолчанию выводится как `HH:MM:SS`, часы не сбрасываются после 24. |
| `azi` | Направление GPS в градусах от −180° до 180°. |
| `cog` | Курс GPS в градусах, приведённый к диапазону 0°–360°. |
| `lat` | Сглаженная широта GPS в десятичных градусах. |
| `lon` | Сглаженная долгота GPS в десятичных градусах. |
| `gps-dop` | Точность GPS из FIT, в метрах, если значение записано. |
| `timestamp` | Время точки в секундах от начала Unix-эпохи (1 января 1970 года UTC). |
| `gps-packet` | Номер точки трека GPX, начиная с нуля. |
| `gps-packet-index` | Индекс пакета GPX; сейчас импортёр GPX задаёт значение `0`. |
| `gps-lock` | Статус GPS для GPX; сейчас импортёр GPX задаёт значение `3`. |

Эти встроенные идентификаторы текущие импортёры FIT и GPX не заполняют: `accl.x`, `accl.y`, `accl.z`, `grav.x`, `grav.y`, `grav.z`, `ori.pitch`, `ori.roll`, `ori.yaw`. Параметр `custom_field="true"` может прочитать одноимённое скалярное поле из сообщения `record` или `session`, если оно там есть; массивы датчиков из других FIT-сообщений он не распаковывает.

## Примеры Developer Fields

Эти имена и единицы встречаются в одном FIT-файле. При использовании в `metric` сохраняйте регистр и пробелы:

| Имя поля FIT | Единицы в FIT | Сообщение |
| --- | --- | --- |
| `Battery Level` | `%` | `record` |
| `Gps Level` | — | `record` |
| `GAP Pace` | `min/km` | `record` |
| `Anaerobic Reserve` | `%` | `record` |
| `Sustainable Pace` | `min/km` | `record` |
| `Accumulated Work` | `kJ/kg` | `record` |
| `Carbohydrate Remaining` | `g` | `record` |
| `Eccentric Load` | `m` | `record` |
| `Critical Speed` | `m/s` | `session` |
| `D Prime` | `m` | `session` |

Виджет `metric` выводит числовое значение и сам не добавляет единицы FIT; при необходимости добавьте текстовую подпись. Если несколько Developer Fields имеют одинаковое имя, загрузка завершится ошибкой неоднозначности, а не выберет одно из них молча.

## Особенности расчётов

- `gradient` использует накопленную дистанцию FIT, только если она есть у всех точек и не убывает. Точки сопоставляются на расстоянии не менее 10 м. Уклон не рассчитывается, если разница дистанций не превышает 1 м, у одной из точек нет 3D GPS-позиции или высоты либо результат выходит за пределы ±80%. Полная, но убывающая серия дистанции FIT сейчас не даёт значения уклона.
- Если дистанция FIT неполная, временной уклон рассчитывается по окнам 3, 30 и 120 секунд. Производная вертикальная скорость использует те же окна, если в записи нет готового значения; у обеих точек должны быть 3D GPS-позиция и высота. Для адаптивных метрик выбираются 30 секунд при темпе медленнее 20 мин/км и 120 секунд — медленнее 30 мин/км.
- `pace` выбирает между оценками скорости за 3 и 30 секунд; окно 30 секунд используется при темпе медленнее 20 мин/км. Темп недоступен при скорости 0,05 м/с или ниже; пересчёт ограничен 500 мин/км.
- Записанная скорость сглаживается фильтром Калмана с параметрами исходного проекта. Координаты GPS сглаживаются экспоненциально с коэффициентом 0,45 до расчёта дистанции маршрута, скорости и направления.
- Беговой каденс переводится из оборотов в минуту в шаги в минуту умножением на два. Велосипедный каденс остаётся в оборотах в минуту.
- Запасной расчёт дистанции GPS использует сферическую формулу гаверсинусов со средним радиусом Земли. Он быстрее, но немного отличается от расчёта по эллипсоиду WGS84, используемого в исходном проекте.
